# SAHAYOG MULTI-DEVICE ARCHITECTURE PROGRESS LOG

## Date: 2026-09-16
## Project: Sahayog Service Cooperative (Multi-Device Demo)

### 1. Architecture Overhaul Overview
- Transitioned Sahayog from a single-device mock/admin prototype to a real Multi-Device Hub & Spoke service marketplace.
- Roles: Strictly 2 roles:
  1. CUSTOMER (Creates service requests with any combination of skills & quantities)
  2. PROVIDER / WORKER (Views matching requirements based on skill intersection, accepts assignments)
- Sahayog Hub: Dedicated app/network operating mode (not a user role). One Android device runs as the authoritative Hub hosting an embedded HTTP server on port 8989, managing state, handling routing, and persisting requests to local storage.
- Admin role completely removed from app navigation, startup wizard, and state models.

### 2. State & Data Models Modified
- Models.kt:
  - Removed `Role.COOPERATIVE_ADMIN`. Only `CUSTOMER` and `WORKER` exist.
  - Added `ServiceRequirement(skill: String, quantity: Int, assignedProviderIds: List<String>, assignedProviderNames: List<String>)`.
  - Updated `Job` model to contain `requirements: List<ServiceRequirement>`.
- UserPreferences.kt:
  - Updated `UserProfile` to support `skills: List<String>` and `customerServiceInterests: List<String>`.
  - Removed admin fields (`cooperativeBranch`, `adminPosition`).
  - Added `updateWorkerSkills()`.
- AppDataStore.kt:
  - Updated DataStore keys and serialization to match multi-skill worker preferences and remove admin properties.
